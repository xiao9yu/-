## 一、项目背景

### 1.1 政策与行业驱动

**政策驱动**。国家层面对职业教育数字化转型与人工智能赋能教育持续加码：《教育信息化2.0行动计划》（教育部，2018）提出"三全两高一大"发展目标，推动信息技术与教育教学深度融合；《国家职业教育改革实施方案》（国发〔2019〕4 号，即"职教 20 条"）明确要求推进职业教育信息化教学，适应"互联网+职业教育"发展需求；教育部等九部门《关于加快推进教育数字化的意见》（2025）进一步部署人工智能赋能教育教学的规模化应用，为高职院校建设智能化教学环境提供了明确的政策依据。

**行业驱动**。以 DeepSeek 为代表的大模型将推理成本大幅拉低，中文理解与结构化输出能力成熟；语音识别（ASR）、光学字符识别（OCR）、多格式文档解析等多模态感知技术均可本地离线部署；向量检索、混合检索、知识图谱等 RAG 配套开源生态完善。AIGC 技术进入教育领域的门槛已显著降低，"大模型 + 智能体（Agent）"正在成为教育信息化产品的标准技术形态。

**院校驱动**。高职院校生源多元（普高、中职、单招等），人才培养强调技能导向，教师人均承担课程门数多、备课与命题任务重，院校对"备、教、学、评、就"全链条的智能化工具需求迫切。建设一个贴合高职场景的教育智能体平台，既响应政策导向，也直击一线教学与就业工作的真实需求。

### 1.2 高职院校核心痛点

经对高职院校典型工作场景的调研归纳，核心痛点集中在四个方面：

| 编号 | 核心痛点 | 典型表现 |
|---|---|---|
| P1 | 教师备课负担重 | 每门课的教案、课件、习题、月考试题编制耗时长、重复劳动多；校本资源分散，检索引用困难 |
| P2 | 学生基础差异大 | 生源多元导致知识基础参差，统一教学难以适配个体水平；缺乏个性化学习路径与针对性练习 |
| P3 | 行政流程低效 | 教务通知、数据汇总、资料整理等事务性工作占用大量人力，信息化程度不足 |
| P4 | 面试就业数据缺失 | 就业指导老师靠人工记录面试情况，信息零散、无结构化复盘，学生面试能力提升缺乏针对性反馈 |

### 1.3 技术成熟度

| 技术方向 | 成熟度判断 |
|---|---|
| 大模型 | DeepSeek 等国产大模型中文理解与 JSON 结构化输出成熟，OpenAI SDK 兼容生态完善，按量付费成本极低 |
| 智能体（Agent） | LLM 网关 + 工具调用模式成熟，可支撑"生成 → 编辑 → 导出"等复杂业务链路的编排 |
| 多模态与感知 | FunASR 语音识别、PaddleOCR 图文识别、多格式文档解析均具备本地离线部署能力，无需 GPU |
| 数据整合 | RAG（混合检索 + 重排）与知识图谱（Neo4j）在教育场景已有成熟实践，开源组件完备 |

结论：上述技术均为 AIGC 主流方案且可低成本落地，以实训项目形式交付教育智能体平台的条件已经具备。

### 1.4 项目建设目标与范围

**建设目标**：面向高职院校，交付一个覆盖"智能备课、智能助教、个性化学习推荐、面试 AI 复盘"四大场景的教育智能体平台，用 AIGC 技术缓解上文 P1~P4 四类核心痛点。

**建设范围**：本项目由实训工单 16~20 共 5 份工单组成。工单 16 为需求分析与软件架构设计（本文档）；工单 17~20 为四个功能模块的前后端实现，每工单含代码、UML/接口/数据库设计、测试用例及结果。

**总体路线**：采用"单体平台 + 按工单顺序垂直交付"方案（17→18→19→20）；公共底座（认证、LLM 网关、文件服务、文档解析管线、RAG 引擎）一次建设、四个模块复用。

## 二、需求分析

### 2.1 目标用户分析

平台面向四类用户角色（与系统 RBAC 权限模型一致），各类用户的痛点与诉求如下：

| 用户角色 | 典型使用者 | 核心痛点 | 核心诉求 | 主要使用模块 |
|---|---|---|---|---|
| 教师 | 专业教师、教研室主任 | 备课负担重（P1）；校本资源检索难 | 一键生成教案/课件/习题/月考试题；校本资源引用；富文本编辑与多格式导出；版本回溯 | 工单 17 智能备课、工单 18 智能助教 |
| 学生 | 在校学生 | 基础差异大（P2）；学习路径不清晰；错题缺乏深度解析 | 个性化学习路径与可解释推荐；自适应难度练习；错题解析与变式训练；面试能力提升 | 工单 19 个性化学习推荐、工单 20 面试 AI 复盘（本人记录） |
| 就业指导教师 | 就业处/辅导员 | 面试数据零散、复盘凭经验（P4） | 面试记录统一管理与批量导入；录音自动转写与结构化评分；AI 优化回答示范 | 工单 20 面试 AI 复盘 |
| 管理员（校务管理者） | 教务/信息化管理员 | 知识资产散落、管理效率低（P3） | 公共知识库预置与维护；用户与角色管理；平台运行数据总览 | 系统管理、工单 18 公共库管理 |

### 2.3 非功能需求与需求优先级

| 类别 | 需求要点 |
|---|---|
| 性能 | LLM 流式输出降低首字等待；向量检索与重排在本地 CPU 环境满足交互级响应 |
| 可靠性 | LLM 网关超时 3 次指数退避重试；JSON 解析失败自动修复重试；失败降级为友好提示（不白屏）；FastAPI 全局异常处理器返回结构化错误 JSON |
| 安全性 | JWT 认证 + RBAC 角色权限；私有库数据隔离；密码 bcrypt 哈希；上传文件类型白名单（详见第五章） |
| 可扩展性 | 向量库、数据库、图谱组件均封装可替换接口（Milvus↔FAISS、SQLite→MySQL、Neo4j 退化方案） |
| 可演示性 | 预置一套人工智能专业课程演示数据（教材 PDF、PPT、试题、面试录音样例），验收现场直接演示全链路 |

## 三、软件设计架构

### 3.1 总体架构

本项目采用**单体平台 + 四层架构**：前端层（Vue3）→ 后端层（FastAPI）→ 智能服务层 → 数据层。四层职责清晰、接口明确，智能服务层各组件可独立测试。

```
┌─────────────────────────────────────────────────────┐
│ 前端层  Vue3 + Vite + Element Plus + Pinia + Router │
│        登录 → 首页仪表盘 → 智能备课/智能助教/       │
│        个性化学习/面试复盘 四个模块页               │
├─────────────────────────────────────────────────────┤
│ 后端层  FastAPI（REST API + JWT 认证）              │
│        /auth  /prep(备课)  /kb(知识库问答)           │
│        /learn(推荐)  /interview(复盘)  /files       │
├─────────────────────────────────────────────────────┤
│ 智能服务层                                           │
│  LLM网关(DeepSeek)  RAG引擎(混合检索+重排)          │
│  文档解析管线(多模态)  ASR服务(FunASR)  画像/推荐    │
├─────────────────────────────────────────────────────┤
│ 数据层  SQLite(SQLAlchemy,可切MySQL) + Milvus Lite   │
│        向量库 + Neo4j 知识图谱 + 本地文件存储        │
└─────────────────────────────────────────────────────┘
```

模块间通过定义清晰的接口通信，每个服务可独立测试。

### 3.2 详细分层说明

#### 3.2.1 前端层

- **职责**：面向四类用户的交互界面与状态管理，包括登录认证、首页仪表盘、四个模块业务页面、引用溯源卡片、画像雷达图等。
- **组件清单**：Vue3 + Vite 构建；Element Plus 组件库；Pinia 状态管理；Vue Router 路由；wangeditor 富文本编辑器。
- **接口关系**：仅通过后端 REST API 交互（请求携带 JWT），不直连数据层与智能服务层，保持前后端分离的代码交付形态。

#### 3.2.2 后端层

- **职责**：REST API 提供；JWT 认证与 RBAC 鉴权；业务编排（按模块调用智能服务层组件）；全局异常处理（所有接口返回结构化错误 JSON）；文件上传/下载/预览。
- **组件清单**：FastAPI 应用；路由模块 `/auth`（登录注册）、`/prep`（智能备课）、`/kb`（知识库问答）、`/learn`（学习推荐）、`/interview`（面试复盘）、`/files`（文件服务）。
- **接口关系**：上行接收前端请求；下行以服务接口方式调用智能服务层组件；经 SQLAlchemy、pymilvus、Neo4j 驱动访问数据层。

#### 3.2.3 智能服务层

平台智能能力的核心，四个模块复用：

| 组件 | 职责与要点 |
|---|---|
| LLM 网关 | DeepSeek 调用统一封装：超时 3 次指数退避重试、流式输出、JSON 结构化解析与失败自动修复、用量日志；各模块只调网关，不直连 API |
| RAG 引擎 | Milvus 向量检索 + BM25 关键词检索混合 → RRF 融合粗排 → bge-reranker 精排 → 返回带原文出处与图片引用的结果 |
| 文档解析管线 | PDF/Word/PPT/Excel/图片 → 文本块/表格块/图片块（OCR 文字 + 原图引用）/公式块 → 分块 → bge-m3 向量化；工单 18 为主用户，工单 17 资源检索复用 |
| ASR 服务 | 本地 FunASR（paraformer-zh）离线语音转写，支撑工单 20 面试录音 |
| 画像与推荐服务 | 学生画像更新（行为加权 + 时间衰减）、Neo4j 知识图谱路径推荐、numpy 协同过滤、自适应练习难度控制 |

- **接口关系**：被后端层业务路由调用；调用数据层读写；LLM 网关对外访问 DeepSeek API（唯一外部依赖）。

#### 3.2.4 数据层

### 3.4 模块核心链路

**工单 17 智能备课**：教师登录 → 填课程信息（课程名/章节/教学目标/课时）→ 选生成类型（教案/课件大纲/习题/案例/月考试题）→ 经 LLM 网关（如需校本资源，先 RAG 检索拼入 prompt）→ DeepSeek JSON 结构化生成初稿 → 前端 wangeditor 富文本编辑 → 插入多媒体 → 导出 Word/PPT/PDF → 每次保存存版本快照，支持历史回溯。

**工单 18 智能助教**：师生上传文档（PDF/Word/PPT/Excel/图片）到私有库或公共库 → 多模态解析（文本块/表格块结构化/图片块 OCR+原图/公式块 图片+LaTeX）→ 分块 → bge-m3 向量化入 Milvus → 提问 → 私有库+公共库各取向量 top-k 与 BM25 top-k → RRF 融合 + bge-reranker 精排 → DeepSeek 流式生成回答，附引用出处（文件名+位置）+ 原文摘录 + 图片/表格直接展示。

**工单 19 个性化学习推荐**：初始化（复用工单 17 课程教案与试题）→ 首次登录诊断测试（17 的试题）或导入历史成绩 → 初始画像 → 仪表盘（画像雷达图 + 推荐学习路径 + 今日任务）→ Neo4j 知识图谱：未掌握知识点 + 前置依赖拓扑排序，前端展示"为什么推荐学这个"（可解释性）→ 自适应练习（正确率>80% 升难度、<50% 降难度）→ 答错自动入 AIGC 错题本（解析 + 错误原因 + 2~3 道变式题）→ 画像随答题、助教提问等行为持续迭代（加权 + 时间衰减）。

**工单 20 面试 AI 复盘**：面试列表（学生填报 + 就业指导 Excel 模板批量导入）→ 上传录音 → FunASR 转文字 → DeepSeek 文本纠错 + 问题提取（Q&A 结构化）→ 每题 1~10 评分 + 点评（结合岗位核心技术点知识库）→ 总体评分 + 总评 + 自我介绍点评 + 改进建议 → 复盘详情页（总体评价区 / 问题解析区 / 面试对话区：左 AI 优化版回答、右完整原记录对照）。

### 4.1 技术选型总览

| 层/场景 | 选型 | 理由 |
|---|---|---|
| 大模型 | DeepSeek API chat 模型 | 便宜稳定，OpenAI SDK 兼容，JSON 模式输出结构化内容 |
| Embedding | 本地 bge-m3（sentence-transformers，CPU 可跑） | DeepSeek 无 embedding API；本地免费离线，中文效果好 |
| 向量库 | Milvus Lite（pymilvus 本地模式，无需 Docker） | 工单 17 推荐（Milvus/FAISS/ES 中选 Milvus）；FAISS 作兜底，接口封装成可切换 |
| 重排序 | RRF 融合（向量+BM25）粗排 → 本地 bge-reranker 精排 | 满足工单 18 重排序要求，零额外 API |
| 文档解析 | PyMuPDF / python-docx / python-pptx / openpyxl + PaddleOCR | 全本地免费，覆盖工单 18 多模态要求（文本/表格/图片/公式） |
| 语音识别 | 本地 FunASR（paraformer-zh） | 离线无限用 |
| 知识图谱 | Neo4j Community（Windows 一键安装） | 工单 19 建议；装不上则退化为 SQL 表 + networkx，不影响验收 |
| 业务数据库 | SQLite（开发期）+ SQLAlchemy | 零安装；模型即"数据库设计"产出物，切 MySQL 只改配置 |
| 前端 | Vue3 + Vite + Element Plus + Pinia + wangeditor 富文本 | 前后端分离代码交付 |

### 4.3 选型原则小结

本项目技术选型遵循三条原则：

1. **本地优先、按量付费**：向量化（bge-m3）、检索（Milvus Lite）、重排（bge-reranker）、解析（PyMuPDF 等 + PaddleOCR）、语音（FunASR）、图谱（Neo4j）全部本地免费运行，仅 LLM 生成环节按量付费（DeepSeek API，约 ¥10/月），全项目除大模型外无外部付费依赖。
2. **接口可替换**：向量库（Milvus↔FAISS）、数据库（SQLite→MySQL）、图谱（Neo4j→SQL+networkx）、Embedding 模型（bge-m3→bge-small-zh-v1.5）均封装为可切换接口，单点风险不阻塞交付。
3. **AIGC 主流路线**：整体方案为 RAG（混合检索 + 重排）、Agent（LLM 网关编排）、知识图谱、ASR 多模态的组合，均为当前 AIGC 教育产品的主流技术路线。

## 五、数据安全与合规

### 5.1 认证与访问控制

- **JWT 认证**：统一登录签发 JWT，接口级校验，配合过期与刷新机制；未认证请求一律拒绝。
- **RBAC 角色权限**：教师/学生/就业指导/管理员四角色，接口按角色鉴权（如公共库维护仅管理员、面试批量导入仅就业指导）。
- **密码安全**：密码 bcrypt 哈希后存储，不可逆，杜绝明文与可逆加密。

### 5.2 数据隔离与权限

- **私有知识库隔离**：检索严格按 `user_id`（owner）过滤，用户仅能检索自己的私有库与公共库，杜绝越权访问他人知识资产。
- **学生数据权限**：学生仅可访问本人画像、练习记录、错题本与本人面试记录。
- **面试数据权限**：面试记录仅学生本人与就业指导（按授权范围）可访问。
- **公共库管理**：公共知识库由管理员预置与维护，普通用户只读。

### 5.3 数据保护与存储安全

- **上传文件类型白名单**：仅允许 PDF/DOC/DOCX/PPT/PPTX/XLS/XLSX/图片/音频等业务格式，防止恶意文件上传。
- **本地化存储与处理**：文件与数据库全部本地存储；向量化、ASR 转写、OCR 全部本地运行，仅必要文本经 LLM 网关送 DeepSeek API（最小必要原则），面试录音等敏感数据不出本地。
- **数据加密存储**：数据库与文件均为本地单机存储；敏感数据（如面试录音）可按需加密落盘，实训范围内暂不作强制要求（设计文档未规定加密要求，此处如实说明口径）。
- **敏感数据脱敏**：对外展示的面试记录、学生信息做脱敏处理（隐藏联系方式等非必要字段）。
- **操作审计**：LLM 网关记录用量日志，支撑成本核算与异常排查。

### 5.4 法规合规要点

| 法规 | 合规要点 | 本项目落地措施 |
|---|---|---|
| 《数据安全法》 | 数据分类分级、处理活动合规、全生命周期保护 | 面试录音、成绩、画像列为敏感业务数据；全链路本地存储处理；访问按角色最小授权 |
| 《个人信息保护法》 | 处理个人信息遵循最小必要与告知同意；敏感个人信息严格保护 | 仅采集教学/就业必要信息；面试录音属敏感个人信息：仅学生本人与就业指导教师可访问、对外展示脱敏、约定留存期限与删除机制；数据不出本地 |

### 5.5 安全措施清单

| 措施 | 实现方式 | 防护目标 |
|---|---|---|
| 密码保护 | bcrypt 哈希 | 账户凭据泄露 |
| 认证与鉴权 | JWT + RBAC 四角色 | 未授权访问 |
| 数据隔离 | 私有库按 owner 过滤；学生数据按本人过滤 | 越权访问数据 |
| 上传防护 | 文件类型白名单 | 恶意文件上传 |
| 存储安全 | 本地化存储 + 敏感数据脱敏 | 数据外泄、隐私泄露 |
| 合规运营 | 最小必要、告知同意、留存期限 | 法规合规风险 |

## 七、总结与展望

### 7.1 文档总结

本文档围绕高职院校"教师备课负担重、学生基础差异大、行政流程低效、面试就业数据缺失"四类核心痛点，完成了教育智能体平台的需求分析与软件架构设计：

1. **需求分析**：明确了教师/学生/就业指导教师/管理员四类用户的痛点与诉求；将工单 16 的六大功能场景映射为四个功能模块（工单 17~20），逐模块给出功能清单与验收标准映射，需求与验收一一对应、无缺项。
2. **架构设计**：采用单体平台四层架构（前端层 Vue3 / 后端层 FastAPI / 智能服务层 / 数据层），公共底座（认证、LLM 网关、文件服务、解析管线、RAG 引擎）一次建设、四模块复用，分层职责清晰、接口明确、可独立测试。
3. **技术选型**：七类场景均采用 AIGC 主流方案——RAG（bge-m3 + Milvus Lite + BM25 + RRF + bge-reranker）、Agent（DeepSeek + LLM 网关编排）、知识图谱（Neo4j）、ASR（FunASR）、多模态解析（PaddleOCR 等），全部本地免费或按量付费（约 ¥10/月），接口可替换。
4. **安全合规**：JWT + RBAC、私有库隔离、bcrypt 哈希、类型白名单、本地化存储与脱敏，落实《数据安全法》《个人信息保护法》要点。
5. **实施计划**：9 人日、D1~D14 排期、2 人日一模块的里程碑节奏，2 周内完成全部 5 份工单交付。

### 7.2 风险与应对

| 风险 | 应对 |

### 7.3 后续展望

平台完成工单 16~20 验收后，可按以下方向持续演进：
