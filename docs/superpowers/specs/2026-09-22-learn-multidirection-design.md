# 个性化学习多方向与题库扩充（Plan G）设计

> 日期：2026-09-22 ｜ 模块：个性化学习（工单19 扩展）+ 备课（知识库出题）+ 知识库

## 一、背景与现状诊断

用户原始诉求（2026-09-22）：

> "个性化学习这个板块里面，虽然有学习方向，但是学习题目每个板块只有一道题，就算下一题了还是一样的题；而且学习方向是只有人工智能方向吗"

现状核实（代码级）：

1. **题目重复根因**：演示种子仅 18 题覆盖 12 个知识点——多数知识点每题档只有 1 道；抽题逻辑按"知识点+难度"过滤后 `random.choice`，池子为 1 时下一题必然重复（`learn_practice.next_question`）。
2. **方向单一**：知识图谱仅「人工智能导论」一门课（12 知识点+前置关系）；`KnowledgePoint.name` 全局唯一、无课程维度——不同方向同名知识点（如"决策树"在 AI 与机器学习都出现）会撞名混画像。
3. **已有基础**：`GET /api/learn/courses` 已列出"有习题集/月考题的课程"；诊断/练习接口已带可选 `course_id`；学习题库本就读取备课课程的习题集/月考题（`collect_questions` 读 `exercises`/`exam` 类型 lesson）——方向维度后端已有雏形，缺的是知识图谱隔离、接口贯通、题库内容与前端切换。

## 三、设计

### A. 数据层（同名知识点课程隔离）

- `KnowledgePoint` 增加 `course_id`（可空，兼容旧库），唯一约束改为 `(course_id, name)`；`name` 单列唯一约束移除。
- 旧数据回填：seed 幂等升级把无 `course_id` 的知识点回填到「人工智能导论」课程（SQLite `ALTER TABLE ADD COLUMN` 缺列时执行）。
- 画像/事件/错题本都经 `kp_id` 关联，知识点课程隔离后**每个方向自然拥有独立雷达图、推荐路径、今日任务与难度进度**；学生原有 AI 方向画像不丢。
- 新方向需重新做该方向的诊断测试（或导入成绩）才会出画像——与"未初始化"引导一致。

### B. 后端接口（方向贯穿 + 三通道）

**学习模块（改）**：

| 接口 | 变更 |
|---|---|
| `GET /api/learn/profile` | 加可选 `course_id`：只返回该课程知识点的画像行（不传 = 全部，兼容旧调用） |
| `GET /api/learn/path` | 加可选 `course_id`：推荐路径只在该课程图谱内拓扑排序 |
| `GET /api/learn/tasks` | 加可选 `course_id`：今日任务只从该课程路径取，抽题必带该课程 |
| `GET /api/learn/wrongbook` | 加可选 `course_id` 过滤错题本 |
| `GET /api/learn/diagnostic`、`GET /api/learn/practice` | 前端改为**必传** `course_id`（不传仍可用=全部课程混池，兼容旧调用） |
| `GET /api/learn/practice` | 加可选 `prev_stem`：候选池 >1 时排除与上一题同题干的题目 |
| `GET /api/learn/courses` | 不变，复用为学习方向列表（返回有习题集/月考题的课程） |

**备课模块（新）**：

- `POST /api/prep/courses/{id}/generate` 扩展 `type=kb_exercises`（知识库出题）：
  - 请求：`{type, 知识点?（逗号分隔）, 难度?, 题数?（默认 10，1~20）}`；
  - 流程：多模态知识库检索（公共库+当前用户私有库，按课程名/知识点关键词 top-k 文本块）→ LLM 按习题 schema 批量出题（prompt 附检索资料原文与"仅依据资料出题"约束）→ `validate_exercises` 校验 → 追加进该课程的 `exercises` 类型 lesson（复用/新建标题为课程名+「知识库生成习题」的 lesson）；
  - 检索空手 → `BizError(404, "知识库中未检索到该课程相关资料，请先上传文档")`；LLM/校验失败 → `BizError(502, "生成失败，请重试")`（既有风格）；
  - 生成即入学习题库：`collect_questions` 无需改动，学生方向题库自动多题。

**三通道落点**：① 月考题/习题自动入池 = 既有链路（补测试）；② 知识库出题 = 上述新接口 + 备课前端按钮；③ 手工种子 = seed 脚本 216 题。

### C. Seed（内容主体，幂等）

- 新建课程：`数据结构与算法`、`机器学习`（Course 行，teacher 名下，类型与现有演示课程一致）。
- 每个新方向：12 个知识点 + 前置关系（内容在计划中逐条列全）+ 72 道选择题（每知识点 易2/中2/难2，题干/选项/答案/解析/知识点/难度六字段，schema 同 `_ex` 工厂）。
- AI 方向：现有「个性化学习演示习题」lesson 的 18 题**补齐到 72**（每知识点补至 6 题；lesson 内容 upsert 更新）。
- 演示知识文档 ×2：`数据结构与算法知识库.md`、`机器学习知识库.md` 入库公共库（覆盖该方向全部 12 个知识点，每知识点 2~4 个要点段落，供知识库出题演示）。
- 幂等：课程按名称判存在；lesson 按课程+标题 upsert；知识点按 `(course_id, name)` upsert；前置关系幂等；迁移（ALTER + 回填 + 唯一约束重建）在 seed 中执行。
- 216 题全部手工起草、逐题核对答案（结构由测试锁定；内容正确性靠计划评审 + 用户彩排实际做题兜底）。

### D. 前端

- **LearnView 学习方向切换**：顶部方向选择器（复用 `GET /api/learn/courses`，默认选中第一个方向）；诊断测试、自适应练习、知识图谱雷达图、推荐路径、今日任务、错题本、成绩导入全部带当前 `course_id` 联动；练习请求携带上一题题干 `prev_stem`；某方向未初始化画像 → 引导先做该方向诊断测试（既有引导按方向化）。
- **备课「从知识库生成习题」**：课程详情页生成入口加按钮（含 题数/难度 输入），成功后提示"已生成并进入学习题库"。
- 验证：`npm run build` + `npx tsc --noEmit`（前端无单测基建）。

### E. 测试与文档

- 后端新用例（计划中列全）：迁移回填与幂等、同名知识点两课程画像隔离、profile/path/tasks/wrongbook 按课程筛选、prev_stem 防重复、月考题自动入池（既有链路钉死）、知识库出题 mock（含检索空手 404、LLM 失败 502、结构校验）、seed 数量与题档分布（216 = 72×3，每知识点每难度 2）、图谱无跨课程前置、诊断测试按课程抽题。
- 全量回归：现有 295 passed, 2 deselected 基线不破 + 新增用例。
- 文档：工单19 测试文档加用例与彩排清单；README 个性化学习小节（三方向、216 题、三通道）与质量基线更新。

## 四、能力边界（不做）

- 学生端即时 LLM 出题（慢/贵/质量不稳）——出题是教师/备课侧批量能力。
- 跨方向推荐、自动切换方向、方向级相似学生（相似学生保持全局用户级）。
- 知识库出题的内容正确性自动化保证（结构校验 + 人工复核兜底）。
- 数字人讲课视频生成（2026-09-22 用户拍板搁置）。
- 旧库已有跨方向同名知识点：本库演示数据无此情况；迁移按"无课程归属的旧知识点一律回填 AI 课程"处理。

## 五、降级与兼容

| 场景 | 行为 |
|---|---|
| 知识库出题检索空手 | BizError 404，提示先上传相关文档 |
| LLM 不可用/超时/JSON 非法 | BizError 502"请重试"（既有风格），不落库 |
| 旧前端调用（不传 course_id） | profile/path/tasks/wrongbook/diagnostic/practice 全部兼容（=全部课程） |
| 旧数据库 | seed 幂等升级：ALTER 加列 + 回填 + 约束重建；画像/事件数据不动 |
| 学生切换方向未初始化 | 该方向引导先诊断测试（既有 400 文案按方向呈现） |
