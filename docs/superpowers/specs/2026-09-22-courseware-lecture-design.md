# 课件数字人讲课模式设计（2026-09-22）

## 0. 为什么做、砍掉了什么

教师生成课件后只能得到一份 PPTX 文件，学生端没有"被讲一遍"的体验；而数字人朵娅（Plan E）
已具备完整的朗读 + 口型对齐能力，把两者接起来就是"数字人讲课"。**本功能把备课从"生成课件"
延伸到"数字人把课件讲出来"**，并让导出的 PPTX 自带讲稿备注，教师放映时照稿讲解。

设计前与用户裁定的范围（决策记录）：

| 决策项 | 结论 | 理由 |
|---|---|---|
| 讲稿来源 | AI 生成：生成课件大纲时顺带产出每页讲稿 | 听感像真人串讲，不增加额外点击 |
| 数字人 | 保持 2D 朵娅，不换 3D | 朵娅朗读/口型/打断全是验证过的成品，换 3D 等于重做一遍；市面 3D 讲课视频是付费商业 API，会把项目亮点外包 |
| 视频导出 | V1 不做内置录制/后台渲染 | 系统录屏（Win+G）录讲课模式即可，效果等价、零工作量 |
| PPT 嵌入 | 讲稿写入备注栏（不加形象图/视频片段） | PowerPoint 不支持 Live2D 运行时，能落地的只有备注/静态图/视频片段；备注是最有用的 |
| 前端归属 | 控制器直接实现 | Plan D Task 7、Plan E Task 6/7 先例 |
| 界面形态 | 课件预览页内讲课态（不新开路由） | 与现有预览页融为一体、改动小 |

## 1. 数据：课件 JSON 增加讲稿字段

### 1.1 结构

课件（lesson_type=cw）的 `content_json` 从 `{标题, 幻灯片[{标题, 要点[]}]}` 扩为：

```
{标题, 幻灯片[{标题, 要点[], 讲稿}]}
```

- 讲稿 = 该页的**口语化串讲**（2~4 句），面向学生讲课的口吻；开场页可含欢迎语，过渡页可含"接下来我们看……"。
- 讲稿只进 `Lesson.content_json`，**无表结构变更**；不单独建表（讲稿与课件同生共死，随版本走）。

### 1.2 旧课件兼容

已生成的课件没有讲稿字段。处理口径：

- **讲课模式降级**：无讲稿的页朗读要点（按顿号/换行拼接），讲课不中断。
- **提示**：讲课态顶部出现一次性提示"该课件生成于讲课功能上线前，重新生成可获得完整讲稿"。
- 重新生成（现有"重新生成"按钮）即产出带讲稿的新版本，无需迁移脚本。

### 1.3 校验

`validate_courseware` 收紧为与现有风格一致的严格校验：每页必须含非空字符串讲稿，缺失即
502「生成结果缺少讲稿，请重试」。理由：讲稿是讲课模式的主语料，缺页讲稿会让该页体验断裂；
LLM 输出不全时重试一次的成本远低于静默接受后逐页查缺。

## 2. 后端改动（两处，零新端点）

### 2.1 prep_generator.py

- `_COURSEWARE_PROMPT`：幻灯片每项增加「讲稿」，并在提示词中约束：口语化、面向学生串讲、
  不照念要点原文、每页 2~4 句、不用 markdown 与引用编号（复用 TTS 朗读清洗的同一口径）。
- `validate_courseware`：按 §1.3 校验。

### 2.2 prep_export.py：讲稿写进 PPT 备注

`export_courseware_pptx` 导出时，为每页讲稿生成备注页（notesSlide）：

- python-pptx 无备注 API，走 XML 注入：创建 `notesSlide` part + 关联关系，正文段落写讲稿全文。
- 无讲稿的页跳过备注（旧课件导出行为与现在完全一致，无破坏性）。
- 讲稿写入前过一遍 `tts_service.spoken_text` 同款清洗？——**不做**：备注是给人看的，
  引用编号/markdown 无碍阅读；清洗只属于朗读路径，保持各司其职。

### 2.3 明确不做

- 不加任何新 API 端点：TTS 复用现有 `/api/voice`（前端 `speakTextTimed`，含 WordBoundary
  口型时间轴）；课件内容复用现有 lesson 详情接口。
- 不做形象图嵌入 PPT（Live2D 纹理拼图当形象图观感差，需离线渲染定妆照，YAGNI）。

## 3. 前端：PrepEditorView 内讲课态

### 3.1 入口与布局

- 仅 lesson_type=cw 的课件显示工具栏「数字人讲课」按钮；点击进入讲课态。
- 讲课态布局（复用 UI 口味：深墨控制条、统一面板）：
  - **左**：数字人朵娅（复用 `Live2DAvatar`，比例取景同智能助教）。
  - **右**：当前页预览（复用现有课件预览渲染，当前页高亮）。
  - **底**：控制条 = 播放/暂停、上一页、下一页、停止、静音 + 页码指示（第 n / 共 m 页）。
  - **字幕**：当前页讲稿全文展示（读到的内容人眼可跟）。
- 退出讲课态：停止按钮或右上角关闭；切走路由时同样停止播放并释放音频资源。

### 3.2 播放流程

1. 点「播放」：**在同一手势内**同步创建/恢复 `AudioContext`（Plan E 真机教训 cfa5b11：
   Chrome 自动播放策略只在手势内放行，否则无声且口型不动）。
2. 当前页取讲稿（无则要点拼接）→ `speakTextTimed` 合成（带 marks 口型时间轴）→
   `PlaybackManager.enqueue` 播放；marks 驱动朵娅口型（复用 `utils/lipsync.ts` 链路）。
3. 队列播完 → 若还有下一页自动翻页并续播；末页播完自动停止（播放键回到可点状态）。
4. 手动翻页 = 清空队列掐断当前朗读，切到目标页（不自动续播，等用户再点播放）。
5. 静音 = 停口型不停字幕（与智能助教静音语义一致）。

### 3.3 复用清单（全部现成）

| 资产 | 来源 |
|---|---|
| Live2D 数字人组件 | `components/live2d/Live2DAvatar.vue` |
| 音频播放器（队列 + marks 时间轴） | `utils/audio.ts` 的 `PlaybackManager` |
| 口型包络计算 | `utils/lipsync.ts` |
| TTS HTTP 接口封装 | `api/voice.ts` 的 `speakTextTimed` |
| 课件内容获取 | 现有 `api/prep.ts` lesson 详情 |

## 4. 降级与错误处理

| 场景 | 行为 |
|---|---|
| 单句 TTS 合成失败 | 跳过该句继续（现有 TTS 语义），字幕照常显示 |
| 整页无讲稿 | 朗读要点拼接 + 一次性提示"重新生成可获得讲稿" |
| 非 cw 教案 | 不显示讲课按钮 |
| 讲课中切走路由/组件卸载 | 停止播放、释放音频资源，不残留声音 |
| LLM 讲稿缺失 | 生成时 502 提示重试（§1.3），不产生残缺课件 |

## 5. 测试与验收

### 5.1 后端 TDD（pytest，从 backend/ 跑）

- `validate_courseware`：某页缺讲稿/讲稿为空串 → 502；全页含讲稿 → 通过。
- 导出 PPTX：notesSlide 存在且包含讲稿文本（unzip 读 XML 断言）；旧课件（无讲稿）导出不产生
  notesSlide、其余行为与现状一致。
- 生成提示词不直接断言长文本：测试锁结构（讲稿键出现在要求的 JSON 键列表中）即可，防提示词
  微调引发脆断言。

### 5.2 前端

- `npm run build` 通过 + tsc 0 错误（现有验收手段，无单测基建）。
- 浏览器人工彩排（用户执行，回填测试文档）：teacher 登录 → 智能备课 → 课件 → 讲课按钮 →
  播放/翻页/暂停/停止/静音、旧课件降级朗读、TTS 失败降级。

### 5.3 基线

## 6. 能力边界（V1 明确不做）

- 不做视频导出（内置录制/后台渲染），录屏交给系统工具。
- 不做 PPT 内嵌形象图/视频片段（PPT 不支持 Live2D 运行时，静态图观感差）。
- 不换 3D 数字人。
- 不做讲稿二次编辑（讲稿随课件 JSON 走，版本管理、导出、讲课共用同一份数据）。
- 不做学生端自由问答（讲课是单向播放，提问请到智能助教）。
